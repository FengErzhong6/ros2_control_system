# Marvin 双臂末端替换为 Wuji 灵巧手并适配 MoveIt 的修改计划书

## 1. 背景

当前 `marvin_system` 的双臂模型使用的是末端平行夹爪方案，而不是 Wuji 灵巧手：

- `marvin_system/description/urdf/marvin_dual.urdf` 中，左右末端挂载的是虚拟平爪：
  - `ee_L/ee_R`
  - `gripper_L/gripper_R`
  - `left_finger_* / right_finger_*`
- `marvin_system/description/ros2_control/marvin_dual_system.ros2_control.xacro` 中，额外末端关节按 OmniPicker 夹爪建模。
- `marvin_system/hardware/src/marvin.cpp` 中，双臂硬件插件明确要求额外关节必须是 `type=omnipicker`。
- `marvin_system/description/srdf/marvin_dual.srdf`、`motion/config/*`、`bringup/launch/*` 等配置也都是围绕当前平爪结构写的。

与此同时，`asset_description/wuji` 和 `wujihand_system` 已经具备 Wuji 灵巧手的基础描述与单手 `ros2_control` 能力：

- `asset_description/wuji/urdf/wujihand-right.urdf.xacro` 提供了手模型和碰撞网格。
- `wujihand_system/description/ros2_control/wujihand-right.ros2_control.xacro` 提供了单手 20 关节的硬件接口定义。
- `wujihand_system/hardware/wujihand.cpp` 提供了单手 `WujiHandHardware` 插件。

因此，本次改造的目标不是简单替换一个末端 mesh，而是完成一条完整链路：

- 双臂 URDF/Xacro 末端替换为左右 Wuji 灵巧手
- `ros2_control` 中同时管理双臂和双手
- MoveIt 的语义模型、关节限制、控制器、碰撞检测同步适配
- 相关启动链与调试链路能够正常工作

## 2. 改造目标

本次改造的目标定义如下：

1. `marvin_dual` 的左右末端不再使用当前平行夹爪，而是分别挂载一只 Wuji 灵巧手。
2. 左右灵巧手都进入统一的 `robot_description`，可在 RViz 中正确显示视觉和碰撞模型。
3. 双臂与双手都能通过 `ros2_control` 正确发布状态并接收位置命令。
4. MoveIt 能正确加载新的 URDF/SRDF，并在规划场景中考虑灵巧手碰撞体。
5. 保持双臂主规划能力可用，同时为左右灵巧手提供独立控制能力。

## 3. 非目标

以下内容不作为本阶段的硬性目标：

- Manus、摇杆、键盘等高层 teleop 输入直接映射到 20 自由度手指控制
- 灵巧手抓取策略、协同控制、RL 策略联动
- 对现有 `motion_server` 做复杂的手部抓取语义扩展
- 对 Wuji 手运动学求解器做专门优化

这些内容建议放到后续二期或三期处理。

## 4. 当前问题梳理

### 4.1 Wuji 手描述不能直接双实例化

`asset_description/wuji/urdf/wujihand-right.urdf.xacro` 虽然声明了 `prefix` 参数，但目前没有真正把 `prefix` 用到 `link`、`joint`、`parent`、`child`、`mimic` 名称中。

这意味着：

- 左右手如果同时 include，会发生同名 link/joint 冲突
- 不能直接把单手描述复用成双手末端模块

### 4.2 Marvin 现有硬件插件只认 OmniPicker 夹爪

`marvin_system/hardware/src/marvin.cpp` 在解析额外关节时，要求：

- 额外 joint 必须带 `type=omnipicker`
- 额外 joint 只按单自由度夹爪处理

这意味着：

- 不能把 Wuji 手的 20 个关节直接塞进当前 Marvin 硬件插件
- 不能沿用现有 `gripper_L/gripper_R` 的单关节夹爪模型

### 4.3 MoveIt 语义层仍然是“仅双臂 + 平爪假设”

当前 MoveIt 配置只覆盖双臂：

- `marvin_dual.srdf` 中只有 `left_arm`、`right_arm`、`dual_arm`
- `kinematics.yaml` 只配置两条机械臂
- `joint_limits.yaml` 只有 14 个关节
- `moveit_controllers.yaml` 只有 `dual_arm_trajectory_controller`
- 现有 `disable_collisions` 规则仍然引用旧平爪 link

### 4.4 启动链默认仍依赖旧夹爪逻辑

以下启动链或工具默认带有旧夹爪假设：

- `marvin_safe_operation.launch.py`
- `marvin_moveit.launch.py`
- `marvin_dual_joint_gui_control.launch.py`
- `marvin_joint_bag_replay.launch.py`
- `marvin_gripper_teleop.launch.py`
- `marvin_tracker_teleop.launch.py`
- `joy_to_pose.cpp`

其中有些链路必须同步改，有些链路需要先降级、停用或改为“后续支持”。

## 5. 总体技术路线

推荐采用以下架构，而不是继续把手部塞进 `MarvinHardware`：

### 方案选择

采用“一个双臂 system + 两个单手 system”的组合方案：

- `marvin_system/MarvinHardware`
  - 只负责左右两条 7 轴机械臂
- `wujihand_system/WujiHandHardware`
  - 左手一个 system
  - 右手一个 system

### 方案理由

这样做有几个优点：

1. 复用现有 `WujiHandHardware`，避免重写 Marvin 硬件插件。
2. 避免破坏当前 `MarvinHardware` 的双臂控制和安全保护逻辑。
3. 符合 `ros2_control` 支持单个机器人描述中存在多个 `<ros2_control>` system 的典型用法。
4. 后续如果左右手硬件参数不同，也更容易独立配置。

## 6. 分阶段实施计划

### 阶段一：改造 Wuji 手描述为可双实例复用模块

目标：让 Wuji 手描述和其 `ros2_control` 描述都支持左右两只手同时实例化。

需要修改：

- `asset_description/wuji/urdf/wujihand-right.urdf.xacro`
- `wujihand_system/description/ros2_control/wujihand-right.ros2_control.xacro`

主要工作：

1. 将手模型改造成 `xacro:macro`。
2. 为以下名称统一添加 `prefix`：
   - 所有 `link`
   - 所有 `joint`
   - 所有 `parent/child link`
   - 所有 `mimic joint`
3. 保持 mesh 路径仍可通过 `side=left/right` 选择左右手模型。
4. 让 `ros2_control` 宏也支持 `prefix`，例如：
   - 左手：`L_finger0_joint0`
   - 右手：`R_finger0_joint0`

阶段验收标准：

- 单独展开 xacro 后，左右手可同时出现在同一个 robot 中且无重名冲突。
- 左右手的碰撞网格仍然正确引用到 `*_collision.STL`。

### 阶段二：在 `marvin_dual` 中用 Wuji 手替换现有平爪

目标：在双臂模型中完成末端结构替换。

需要修改：

- `marvin_system/description/urdf/marvin_dual.urdf`

主要工作：

1. 删除当前平爪相关结构：
   - `gripper_L`
   - `gripper_R`
   - `left_finger_L_link`
   - `right_finger_L_link`
   - `left_finger_R_link`
   - `right_finger_R_link`
2. 保留或重建末端安装过渡帧：
   - `ee_L`
   - `ee_R`
3. 在 `ee_L` 与 `ee_R` 下分别挂载 Wuji 手：
   - 左臂挂 `side=left`
   - 右臂挂 `side=right`
4. 明确末端安装位姿：
   - 先沿用当前 `ee_joint_L` / `ee_joint_R` 的法兰变换作为第一版
   - 后续根据真实法兰、CAD 或实机安装关系再做精调

阶段验收标准：

- `marvin_dual.urdf` 展开后，左右末端显示为两只 Wuji 手。
- `robot_state_publisher + RViz` 下模型树结构正确，无重复名称或断链。

### 阶段三：重构 `ros2_control` 组合方式

目标：让双臂和双手在同一套机器人描述中正确被控制。

需要修改：

- `marvin_system/description/ros2_control/marvin_dual_system.ros2_control.xacro`
- `marvin_system/package.xml`

主要工作：

1. 让 `marvin_dual_system.ros2_control.xacro` 只保留双臂 14 个关节。
2. 删除其中的 OmniPicker 夹爪 joint 定义。
3. 在 `marvin_dual.urdf` 中额外 include 两个 Wuji 手 `ros2_control` 宏：
   - 一个用于左手
   - 一个用于右手
4. 在 `marvin_system/package.xml` 中补充对 `wujihand_system` 的运行依赖。

阶段验收标准：

- `ros2_control_node` 能成功加载：
  - 1 个 Marvin 双臂硬件 system
  - 2 个 Wuji 手硬件 system
- `/joint_states` 中可以看到双臂与双手全部关节状态。

### 阶段四：补齐控制器配置

目标：让 MoveIt 与调试链路都能正确驱动双臂和双手。

需要修改：

- `marvin_system/bringup/config/marvin_dual_trajectory_controllers.yaml`
- `marvin_system/bringup/config/moveit_controllers.yaml`
- 视需要新增：
  - 左手 trajectory controller 配置
  - 右手 trajectory controller 配置
  - 手部 forward controller 配置

主要工作：

1. 保留现有 `dual_arm_trajectory_controller` 用于双臂主规划。
2. 增加左右手各自的 `joint_trajectory_controller`，分别覆盖 20 个关节。
3. 视调试需求增加手部 `forward_position_controller`。
4. 在 MoveIt 控制器映射中注册：
   - `dual_arm_trajectory_controller`
   - `left_hand_trajectory_controller`
   - `right_hand_trajectory_controller`

阶段验收标准：

- 通过 controller manager 可以成功 spawn 双臂和双手控制器。
- MoveIt 能识别这些控制器，不再只认识双臂控制器。

### 阶段五：重建 SRDF 和 MoveIt 语义配置

目标：让 MoveIt 正确认识“机械臂 + 灵巧手”的新机器人语义结构。

需要修改：

- `marvin_system/description/srdf/marvin_dual.srdf`
- `marvin_system/motion/config/kinematics.yaml`
- `marvin_system/motion/config/joint_limits.yaml`
- `marvin_system/motion/config/ompl_planning.yaml`
- 如有需要，更新 `planning_pipelines.yaml`

主要工作：

1. 修改双臂 group 的 tip link，使其指向新末端定义。
2. 新增手部 group：
   - `left_hand`
   - `right_hand`
3. 视规划需求新增组合 group：
   - `left_arm_with_hand`
   - `right_arm_with_hand`
   - `dual_arm_with_hands`
4. 重新生成 `disable_collisions`：
   - 删除旧平爪 link 的禁碰规则
   - 增加双臂与灵巧手、灵巧手内部的合理禁碰配置
5. 在 `joint_limits.yaml` 中补足全部 40 个手部关节限制。
6. 在 `ompl_planning.yaml` 中为新的 planning group 增加 planner 配置。
7. 在 `kinematics.yaml` 中保持双臂使用现有 IK，手部 group 不强制配置 IK。

阶段验收标准：

- MoveIt 可正常加载新的 URDF/SRDF。
- 新模型不会因为旧平爪 link 引用残留而报错。
- RViz 的 Planning Scene 中能看到完整的双臂双手碰撞模型。

### 阶段六：更新启动链

目标：让主启动、可视化、调试和回放流程与新模型保持一致。

重点修改：

- `marvin_system/bringup/launch/marvin_safe_operation.launch.py`
- `marvin_system/bringup/launch/marvin_moveit.launch.py`
- `marvin_system/description/launch/display_marvin_dual.launch.py`
- `marvin_system/bringup/launch/marvin_dual_joint_gui_control.launch.py`
- `marvin_system/bringup/launch/marvin_joint_bag_replay.launch.py`

主要工作：

1. 所有 xacro 启动参数从“旧平爪开关”过渡到“灵巧手开关”。
2. 启动时正确加载双臂和双手相关控制器。
3. GUI 调试链路从旧夹爪关节名切换到新手部关节名。
4. bag replay 时，关节列表不再只追加 `gripper_L/gripper_R`，而是追加完整手部关节集合。

阶段验收标准：

- 主启动链可以稳定启动 MoveIt、controller_manager、robot_state_publisher、RViz。
- Joint GUI 或 bag replay 能看到新的手部关节。

### 阶段七：处理旧夹爪专用功能的降级或迁移

目标：避免旧逻辑阻塞主功能上线。

涉及模块：

- `marvin_gripper_teleop.launch.py`
- `marvin_tracker_teleop.launch.py`
- `joy_to_pose.cpp`
- 任何默认发布 `/gripper_L_controller/commands`、`/gripper_R_controller/commands` 的逻辑

处理原则：

1. 第一阶段先保证这些链路不影响主系统启动。
2. 如果短期内不能支持 20 自由度手部 teleop，则：
   - 明确标记为暂不支持
   - 或在 launch 中做参数开关，默认不启用
3. 后续如需支持，可单独设计：
   - synergy 映射
   - 姿态到手型映射
   - RL 控制器接入

## 7. 对 `motion_server` 与碰撞保护的影响评估

### 7.1 `motion_server`

当前 `motion_server` 中对平爪有硬编码：

- 读取 `gripper_L/gripper_R`
- 动态创建附着碰撞体
- 发布平爪碰撞 marker

但这部分逻辑是“可选启用”的。若新模型中不再出现 `gripper_L/gripper_R`：

- 相关逻辑大概率会自动失效
- 不会成为第一阶段的主阻塞

建议：

- 第一阶段保留代码，但不要再依赖它控制手部
- 第二阶段再决定是否扩展为“真实灵巧手碰撞同步”

### 7.2 `collision_guard`

当前硬件碰撞保护也包含基于平爪百分比的附着圆柱碰撞体逻辑。

建议：

- 第一阶段先依赖 URDF 自带的灵巧手碰撞网格
- 如果 `collision_guard` 因旧夹爪变量缺失而仅退化为“机械臂 + 手固定姿态”碰撞检测，可接受
- 后续如有必要，再单独扩展为读取 Wuji 手实际关节状态

## 8. 风险与难点

### 风险一：末端安装位姿不准确

如果 `ee_L/ee_R` 到 Wuji 手掌的固定变换不准确，会导致：

- 视觉模型位置不对
- 碰撞检测过紧或过松
- MoveIt 规划末端位姿与实际不一致

应对方式：

- 第一版先使用当前法兰位姿快速打通链路
- 后续通过 CAD、标定或实机测量校正

### 风险二：SRDF 手工维护成本高

灵巧手 link/joint 数量多，手工维护 `disable_collisions` 容易出错。

应对方式：

- 优先使用 MoveIt Setup Assistant 生成新的 SRDF 初稿
- 再对必要项做人工微调

### 风险三：旧启动链残留平爪假设

即使主 MoveIt 启动打通，旧的 teleop、joy、bag replay 仍可能因为找不到 `gripper_L/gripper_R` 而报错。

应对方式：

- 在主链完成后集中清理旧夹爪残留
- 对无法立即适配的链路显式禁用

### 风险四：双手硬件接入时序问题

双臂和双手由多个硬件 system 共同运行时，可能出现：

- 初始化顺序问题
- 控制器激活顺序问题
- 某一手失败导致整体启动失败

应对方式：

- 启动脚本中显式控制 controller spawner 顺序
- 在 mock 模式下优先完成模型验证

## 9. 推荐实施顺序

建议按下面顺序实施，避免一次性改太多导致定位困难：

1. 先改 Wuji 手描述，支持左右双实例和前缀化。
2. 再改 `marvin_dual.urdf`，把旧平爪替换成左右 Wuji 手。
3. 接着改 `ros2_control`，让双臂和双手都能在同一个系统中启动。
4. 然后更新控制器配置和主启动链，先打通 mock 模式。
5. 再重建 SRDF 与 MoveIt 配置，完成规划和碰撞检测。
6. 最后清理旧夹爪 teleop、bag replay、joy 控制等历史链路。

## 10. 交付验收标准

完成本计划后，应满足以下最低验收标准：

1. `marvin_dual` 在 RViz 中显示为双臂 + 左右 Wuji 灵巧手。
2. 展开后的 URDF 中不存在左右手重名 link/joint。
3. `ros2_control_node` 可同时加载双臂 system 与双手 system。
4. `/joint_states` 中能看到双臂与双手全部关节。
5. MoveIt 能正常加载新的 `robot_description` 与 `robot_description_semantic`。
6. 双臂规划功能仍可正常使用。
7. 左右灵巧手可通过各自控制器发送关节轨迹或位置命令。

## 12. 结论

本次改造的核心不是“替换一个末端模型”，而是把 `marvin_system` 当前基于单自由度平爪的整套假设，升级为“机械臂 + 双灵巧手”的完整系统描述。

推荐优先完成以下三件事：

1. 让 Wuji 手描述支持双实例前缀化。
2. 在 `marvin_dual` 中完成真实末端替换。
3. 将 `ros2_control` 架构调整为“双臂 system + 双手 system”。

只要这三步打通，后续 MoveIt、控制器、调试工具的适配就会清晰很多。
